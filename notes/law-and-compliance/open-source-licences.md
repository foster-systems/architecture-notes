title: Open source licences
description: "What open source licences allow and require when a company builds its product on open source code."
why: "Most of a product's code is open source, and each licence sets conditions on its use. A missed copyleft obligation can mean releasing source code or rewriting a component, and acquirers and investors check for it in due diligence."

  - title: Licenses
    author: Open Source Initiative
    url: "https://opensource.org/licenses"
    type: docs
    year: 2026
    note: "The Open Source Initiative's list of licences it has approved as meeting the Open Source Definition. Each entry gives the licence text, its SPDX identifier and a category such as popular, superseded or special purpose. A licence missing from the list, such as the SSPL or the Business Source License, is not open source in the OSI's sense."
  - title: Licenses appendix
    author: GitHub (choosealicense.com)
    url: "https://choosealicense.com/appendix/"
    type: guide
    year: 2026
    note: "A table comparing common licences on what they permit, require and limit. Its columns include patent use, disclosing source, keeping the same licence and whether network use counts as distribution. GitHub runs the site to help projects pick a licence."
  - title: Licenses
    author: Google Open Source
    url: "https://opensource.google/documentation/reference/thirdparty/licenses"
    type: docs
    year: 2026
    note: "A public copy of part of Google's internal rules for using third-party code. It sorts licences by their obligations into categories such as restricted (for example the GPL), reciprocal, notice and permissive. It bars the AGPL, the OSL, the SSPL and the Business Source License from Google's code base."
  - title: GNU Affero General Public License version 3
    author: Free Software Foundation
    url: "https://opensource.org/license/agpl-v3"
    type: docs
    year: 2007
    note: "The full text of the AGPL, published by the Free Software Foundation and hosted by the Open Source Initiative. It differs from GPLv3 mainly in section 13: users who interact with a modified version over a network must be offered its source code. That section is what makes the AGPL reach software offered as a service."
  - title: Using open source code
    author: TODO Group (The Linux Foundation)
    url: "https://todogroup.org/resources/guides/using-open-source-code/"
    type: guide
    year: 2017
    note: "A guide to a baseline compliance programme for using open source code in commercial products, with Ibrahim Haddad as contributor. It sets out who does what, a simple usage policy, a five-stage review from source code scan through legal and architecture review to approval, and a sample usage request form. The TODO Group is a Linux Foundation community of company open source programme offices."
  - title: "ISO/IEC 5230: open source license compliance"
    author: OpenChain Project
    url: "https://openchainproject.org/license-compliance"
    type: spec
    year: 2020
    note: "The OpenChain Project's page on ISO/IEC 5230:2020, an international standard for the key requirements of an open source licence compliance programme. The OpenChain text is free and functionally identical to the ISO version. A company can adopt it by self-certification or with a third-party assessment."
